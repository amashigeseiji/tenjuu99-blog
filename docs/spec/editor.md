# エディタ

ターミナルを使わない作成者が、ブラウザ画面だけでコンテンツ（記事・画像）を作成・編集・公開・管理する領域。ファイルが HTML にどう変換されるか（SSGコア）、公開手段の実現（公開）は扱わない。

## 設定 — `blog.json`

| キー | 既定 | 意味 |
|---|---|---|
| `packages` に `editor` | — | エディタパッケージを有効化する |
| `editor_enable` | 無し（配布されない） | エディタページを配布対象にするか（エディタページの `distribute` がこの値を参照する） |
| `frontmatter_templates` | `[]` | フロントマターテンプレートの一覧（下記） |
| `image_converter` | 無し（パススルー） | 画像コンバーター。ビルトイン名（`"sharp"`）またはユーザー提供コンバーターモジュールのパス（`.` か `/` で始まる。プロジェクトルート起点） |
| `publish` | `{ "means": "git" }` | 公開手段の選択（[公開](publishing.md)） |

## URL ナビゲーション

エディタが表示するもの（表示対象）は URL が特定する。記事は `?md=<記事パス>`、画像は `?image=<画像パス>` で、両者は同時に成り立たない。サイドバーのリンククリック・戻る/進む・URL 直打ち・リロードのどの経路でも、表示は URL から再構成される。切り替えはページ全体の再読み込みではなくその場の表示更新で行われ、サイドバーのアクティブ表示は現在の表示対象に同期する。削除された資源は URL から特定が取り除かれ、移動した画像は新しいパスへ URL が付け替わる。

前提: 編集バッファ（テキストエリアの未保存内容）の持続を設計の前提にしない。新しい UI を足すときは、URL の表現とこの共通機構に載せる。

## サイドバー

左部のナビゲーション領域。「ファイル」「新規作成」「画像」のサイドバータブで表示を切り替える。

- **ディレクトリツリー**: ファイルの一覧をディレクトリ階層に整理して表示する。ディレクトリノードは開閉でき、開閉の展開状態はブラウザの localStorage に保存されてセッションをまたいで保たれる。アクティブファイル（URL が特定している記事）のファイルノードは他と区別して表示され、その親ディレクトリは自動で展開される。
- **公開ステータスの表示**: 各ファイルノードに公開ステータス（未公開・更新あり・公開済み・リモートのみ）が添えられ、ファイルを開かずに識別できる。表示語は公開ステータスラベルが一か所から与え、記事と画像で同じ言葉になる。状態を参照できないときは「不明」。
- **画像タブ**: 画像ライブラリの一覧（後述）。ツリーはディレクトリツリーと同じ描画で、記事のツリーと同じ記号で公開ステータスを示す。

## 記事を書く

テキストエリアへの入力を中心に、保存・プレビュー・画像挿入がボタン操作なしに連なる。

- **自動保存**: テキスト入力が止まると、書いた内容がローカルに保存される。手動の save ボタンは無く、保存はリダイレクトを伴わない。保存はローカルへの書き込みだけで、公開とは別操作。
- **リアルタイムプレビュー更新**: テキスト入力の停止、およびインライン画像挿入の完了を契機に、プレビューがボタン操作なしに更新される。プレビューは保存を経ずに未保存の内容を専用の描画で HTML にし、スタイルの外部参照をインライン化して自己完結した形で `<iframe>` に埋め込む（サーバー再起動中でもプレビューが崩れない）。
- **新規作成**: 「新規作成」タブでファイル名（配置パス）を指定し、フロントマターテンプレートを選んで新しいページを作る。作成されたファイルは公開ステータス「未公開」でローカルに保存され、作成しただけでは公開されない。既存のファイル名は拒否される。既存ファイルを開くときはテンプレートを挿入しない。
- **インライン画像挿入**: 画像をテキストエリアにドロップすると、アップロードされてカーソル位置に `![](/image/...)` の Markdown 画像構文が挿入され、プレビューにその場で反映される。画像保存先パスは編集中の記事パスから自動で決まる（`book/painting/claude-monet.md` なら `<src_dir>/image/book/painting/claude-monet/` 配下）。挿入済みの画像は、その記事の公開対象に自動で含まれる。

### フロントマターテンプレート

特定のディレクトリ配下に新規ページを作るとき、テキストエリアにあらかじめ挿入されるフロントマターの雛形。`frontmatter_templates` の各要素は `path_prefix`（適用先ディレクトリ）と `fields`（変数名と既定値の対）を持つ。新規ファイルのパスに `path_prefix` が前方一致する設定が選ばれ、複数一致すれば最も長いプレフィックスが優先される。一致が無ければ `title` だけの雛形になる。`title` はファイル名から導出され、`---` で囲んだ `key: value` の列として挿入される。

```json
{ "frontmatter_templates": [ { "path_prefix": "book/", "fields": { "title": "", "price": "0", "language": "ja" } } ] }
```

### 画像コンバーター

アップロードされた画像は、コンバーターファクトリーが `image_converter` から組み立てた画像コンバーターで Web 向けのサイズ・フォーマットに変換されて保存される。ビルトインコンバーター `sharp` は幅 1200px を上限に縮小して WebP にする。ユーザー提供コンバーターモジュールは、変換関数（バッファを受けて変換後のバッファを返す）をデフォルトエクスポートし、出力拡張子を `ext` としてエクスポートする（省略時は元の拡張子）。設定が無い、または指定したコンバーターが利用できないときは変換せずに通す。

## 記事を公開する

記事の公開・更新・非公開・削除・取り込みは、開いている記事に対する操作としてエディタから行い、リモートへの反映は[公開](publishing.md)の公開手段に委ねる。

**公開ステータス** は記事ごとのローカル／リモート間の反映状態で、内容差分の読み（一致・不一致・欠如）の現れ。同じ読みが画像にも適用される。

| 状態 | 意味 | 行える操作 |
|---|---|---|
| 未公開 | ローカルのみに存在 | 公開する・削除する |
| 更新あり | リモートと差分がある | 更新する・非公開にする |
| 公開済み | ローカルとリモートが一致 | 非公開にする |
| リモートのみ | ローカルに無くリモートに存在 | 取り込む・非公開にする |
| 不明 | リモートを参照できない | どれも行えない（原因を問わず同一の扱い。公開ボタンは無効化され「状態不明（公開不可）」と示される） |

一度公開したファイルと一度も公開していないファイルは、どちらも「未公開」として区別しない。

- **公開する／更新する**: 同じボタンで、未公開なら公開する（未公開 → 公開済み）、更新ありなら更新する（更新あり → 公開済み）が起動する。公開対象は作成者が選ぶのではなく編集内容から自動で決まり、編集中の Markdown ファイルと、その記事由来のすべての画像参照から集めた画像ファイルで構成される。画像参照には本文画像参照（Markdown 画像記法と、本文に埋め込まれた `<img>` タグ）とフロントマター画像参照（フロントマターの値のうち、ローカルパスかつ画像拡張子という画像パスの形をもつもの。フィールド名では判別しない）がある。スタイルシート経由の参照は含まない。保存も一括して処理される。
- **公開フィードバック**: 実行中・完了・失敗がブラウザ上で知覚でき、サーバーへ接続できなかった場合と操作の失敗は区別して示される。文言は操作実行器に一元化されている。
- **非公開にする**: リモートから記事を取り除き、原稿は手元に残す（再公開できる）。
- **削除する**: 未公開の記事をローカルから取り除く。確認を経て実行され、公開中の記事には提供されない（先に非公開にする）。リモートの状態が確認できないときは削除できない。
- **取り込む**: リモートの内容を手元に反映する（[公開](publishing.md)の同期）。
- **公開後の画面**: 公開ステータスの表示は、ページ読み込み・記事の切り替え・操作の成功後に更新される。

### 画像の公開状態の連動

画像には独立した公開操作が無い。画像公開状態（公開されるべきか）は、公開済みの記事内容からの参照（公開済み参照）または検出外参照宣言の有無から導出される。記事の同期操作（公開・更新・非公開）のたびに画像公開同期器が、その記事が今参照している画像の集合と画像台帳の公開済み参照との差分を反映し、参照を失い宣言も無い画像をリモートから取り除く。公開済みの記事がまだ参照している画像は取り除かれない（疑わしきは消さない）。公開済み参照は同期操作のタイミングでのみ更新され、編集途中の内容は根拠にしない。移動した画像が公開されるとき、リモートに残る移動元パスも取り除かれ、その記録は消える。

## 画像ライブラリ

記事編集を経由しない画像操作の窓口。対象は `<src_dir>/image/` 配下（再帰）。

- **一覧・詳細**: 「画像」タブに、パス・バイト数・解像度・追加日時・公開ステータスを持つ一覧をツリーで示す。追加日時はエディタ経由で追加された画像にだけ記録され、記録の無い画像は「不明」。画像を選ぶと右ペインにプレビューとメタデータ、参照している記事の一覧（公開状態つき）、検出外参照宣言の切り替え、移動・削除の操作がまとまって示される。参照記事一覧は選択時に個別に取得される。画像タブを開くたびに一覧は最新の状態になる。
- **追加**: 「新規作成」タブで画像ファイルを選ぶと、記事の作成ではなく画像の追加として扱われる。配置パスは `<src_dir>/image/` 相対（階層可）で作成者が指定する。同名の既存画像は上書きせず拒否する。追加後はその画像が表示対象になる。追加しただけでは公開されない。
- **削除・移動**: 実行前に参照している記事（公開状態つき）が提示され、参照の扱いを「そのまま」「更新（参照を除去／新しいパスに書き換え）」「中止」から選ぶ。作成者が選ばない限り記事は書き換わらない。「参照も更新」したときは開いている記事が再読み込みされる。移動の入力は `image/` 相対の配置パスで、改名は同じ置き場所への移動として同じ操作に含まれる。画像として扱える名前でない・管理領域の外へ出る・既存の画像と重複する移動先は拒否される。移動した画像は「別の画像が現れた」ではなく「同じ画像の未同期の変更」（更新あり）として読まれる。
- **検出外参照宣言**: テンプレート等、自動検出できない場所で使われている画像を作成者が申告する。宣言された画像は参照切れ扱い・自動非公開の対象にならない。
- **リモートのみの画像**: ローカルに実体が無くリモートにだけ残る画像は、ローカルのツリーとは別の枠に一覧され、そこからリモートから取り除ける（取り込む操作は無い）。

### 画像台帳

画像パスごとの記録を `<src_dir>/image-library.json` に持つ。フィールドは `addedAt`（追加日時）、`publishedReferredBy`（公開済み参照。同期操作時のみ更新され、自動非公開の唯一の根拠）、`protected`（検出外参照宣言）、`movedFrom`（移動元パス。移動を重ねても最初の移動元を保ち、リモートから取り除かれた時点で消える）。台帳は同期される場所に置き、`.cache/` には置かない。エディタの操作の範囲では台帳と実体は整合するが、エディタ外で `image/` を直接操作した場合の整合は保証しない。

## 行為

- 作成者は、編集画面から画像をアップロードすると、Web に適したサイズ・フォーマットに変換されて保存される。
- 作成者は、テキスト入力の手を止めると、preview ボタンなしでプレビューが自動更新され、確認しながら書ける。
- 作成者は、画像をテキストエリアにドロップすると Markdown 構文が挿入され、プレビューでその場で確認できる。
- 作成者は、新規作成ボタンからファイル名とテンプレートを指定して、新しいファイルを未公開の状態で作れる。
- 作成者は、save ボタンを押さなくても、書いた内容がローカルに保存される。
- 作成者は、サイドバーのファイルをクリックしてエディタで開ける。
- 作成者は、サイドバーを見るだけで、各ファイルの公開ステータス（未公開・更新あり・公開済み）を開かずに識別できる。
- 作成者は、サイト全体の画像を一覧・プレビューし、ファイル名・サイズ・解像度・追加日時を確認できる。
- 作成者は、不要な画像を削除でき、参照がある場合は参照記事の提示と選択を経て削除できる。
- 作成者は、画像の置き場所とファイル名を付け替えられ、参照記事の扱いを選べる。
- 作成者は、記事編集を経由せず、画像ファイルと配置パスを指定してサイトに画像を追加できる。
- 作成者は、画像の公開・非公開が、記事からの参照（本文・frontmatter）の有無に連動して決まる。
- 作成者は、画像の選択・表示を URL で特定でき、リロード・URL 直打ち・戻るで同じ表示が再現される。
- 作成者は、画像の公開ステータス（未公開・更新あり・公開済み）を画面で確認でき、リモートに届いていない変更も読み取れる。
- 作成者は、リモートにのみ残っている画像を別枠で見つけ、リモートから取り除ける。
- 作成者は、検出できない参照を宣言して自動非公開から外せる。
