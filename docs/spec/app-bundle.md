# アプリバンドル配布

@tenjuu99/blog を `.app` として自己完結的に配布するための構成・成果物を扱う領域。コード署名・notarization、ビルド・配布パイプライン（CI でのビルド・zip 化・Releases 公開）、編集操作、公開操作は扱わない。

## 配布物の自己完結

配布物は `.app` 単体の成果物で、ネイティブアプリシェルを内包し、Node 本体・sharp のネイティブバイナリ・ソースコード一式（`lib/`・`packages/` 等）を同梱することで、配布先環境への追加インストールを不要にする。Node が入っていない Mac でも Finder からダブルクリックするだけで起動し、編集操作まで行える。未署名のため Gatekeeper の初回警告は起きてよい（回避策は持たない）。

起動時、バンドルレイアウト解決器が実行中の `.app` 自身の場所から同梱リソース（Node 実行ファイル・アプリコードのエントリー・同梱モジュール解決器の登録スクリプト）の場所を導出する。同梱物は配布物の一部として保証されているものだけを扱い、存在しないケースは考慮しない。コンテンツルート解決器は `blog.json` を含むフォルダを確定する（記憶済みならそれを、無ければコンテンツルート選択ダイアログで選ばせる）。選ばれたフォルダに `blog.json` が無ければエラーとし、新規作成はしない。

## 同梱コードの依存解決

同梱コードの一部はビルド時にコンテンツルート配下（`.cache/`）へ複製されて動く。複製後の位置からの依存解決はコンテンツルートの祖先を遡る経路にしかならず、`.app` 内の `node_modules` には辿り着けない。同梱モジュール解決器はこれを埋める装置で、アプリが同梱 Node を起動するときだけ差し込まれ、アプリ自身のパッケージ名（`@tenjuu99/blog` とそのサブパス）への参照と、同梱コード自身の依存パッケージ（依存パッケージ名判定器が同梱コードの `package.json` の `dependencies` から動的に判定する。個別列挙はしない）への参照を、コンテンツルートの中身に関わらず同梱コードへ解決する。解決先はサーバー本体と同一のモジュールインスタンスになり、モジュールレベルの状態（`allData` 等）の共有が保たれる。横取りするのはこれらの参照だけで、それ以外は通常の Node の解決に従う（ヘルパー等はコンテンツルートの実体 `node_modules` に届くので、開発中プロジェクトの独自パッケージも `.app` 上で動く）。

## 同居と既存物保護

既存物保護は、コンテンツルートに選んだフォルダ内の既存ファイル・ディレクトリが利用者の同意なく削除・置換・変更されないという保証で、配布物はコンテンツルートに一切書き込まないことでこれを成立させる。これにより同居 — 同一のフォルダをローカルでの開発（エディタ・npm 等の直接操作）と配布物としてのアプリ利用の両方で使い続けられる状態 — が成り立ち、実体の `node_modules` を持つ開発中プロジェクトをコンテンツルートに選んでも、開発側の成果物とアプリの動作が互いを壊さない。過去の版のアプリがコンテンツルートに作った同梱宛のシンボリックリンクは撤去しない。

## 配布物の組み立て

配布物組み立て器はビルド時に `.app` を組み立てる。同梱対象とその配置先（`entries`）、配布先で意味を持つように張り替えるシンボリックリンク（`symlinks`）はバンドルマニフェスト（JSON）にコード外で宣言され、配置マッピング解決器がそれをビルド成果物（同梱用 Node バイナリ・本番依存のみの `node_modules`・`lib/`・`packages/` 等）の実パスに解決し、バンドル書き出し器が対応表どおりにコピーする。シンボリックリンクは実体化せずそのままコピーし、npm の自己参照リンク（`@tenjuu99/blog` 自身への依存）は `.app` 内で完結する相対リンク（`Contents/Resources/app/node_modules/@tenjuu99/blog → ../..`）に張り替える。

`.app` の中身は、`Contents/MacOS/App`（ネイティブアプリシェル）、`Contents/Resources/node/bin/node`（同梱 Node）、`Contents/Resources/app/`（`index.js`・`lib/`・`packages/`・`package.json`・`node_modules/`・`bin/server`・同梱モジュール解決器の登録スクリプト）。ローカルでの組み立ては `node scripts/app-bundle/build-local.js` で、`dist-app/tenjuu99-blog.app` に出力される。

## 行為

- アプリ利用者は、コンテンツルートの実体 node_modules の有無に関わらず、追加インストールなしに同梱機能を使える。
- アプリ利用者は、実体の node_modules を持つ開発中プロジェクトを、中身を壊されずにコンテンツルートとして使える。
