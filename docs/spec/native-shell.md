# ネイティブシェル

@tenjuu99/blog のサーバー起動とエディタ画面の表示を、1 つのネイティブ Mac ウィンドウのライフサイクルとして統合する領域。編集操作の中身（エディタ）、公開操作（公開）、配布物の組み立てと同梱物の解決（アプリバンドル配布）は扱わない。

## 起動から編集まで

アプリ利用者が配布物を開くと、ネイティブアプリシェルはまずコンテンツルート（`blog.json` を持つプロジェクトのフォルダ）を確定する（アプリバンドル配布のコンテンツルート解決器。コンテンツルート記憶があれば黙ってそれを使い、無ければコンテンツルート選択ダイアログで選ばせる）。続いてサーバーライフサイクル連動がそのフォルダをカレントディレクトリとしてサーバープロセスを起動し、アプリウィンドウは起動待ち表示を出す。サーバー起動完了検知が接続受付可能になったことを確認すると、表示状態判定器の判定に従ってウィンドウ内（WKWebView）の表示がエディタの編集画面に切り替わる。アプリを終了するとサーバープロセスも終了し、残らない。

編集操作（保存・ツリー操作・プレビュー・画像挿入）はウィンドウ内で外部への切り替えなしに行える。編集画面からのファイル選択要求（画像の追加など）には、ファイル選択応答器がネイティブの選択の場を提示し、選ばれたファイル群または取りやめを要求の条件（複数選択の可否）に整合させて要求元へ返す。

前提: エディタはブラウザの永続化として localStorage しか使わず、別ウィンドウ・別タブを開かない。

## プロジェクトの切り替え

コンテンツルート記憶は、選択済みコンテンツルートをアプリの再起動を跨いで保持する（UserDefaults のキー `ContentRootURL`）。記憶がある限り選択ダイアログは出ない。

利用中のプロジェクトを別のプロジェクトへ切り替えるには、「ファイル」メニューの「コンテンツフォルダを変更…」（コンテンツルート切り替えメニュー）からコンテンツルート選択ダイアログを開く。帰結は切り替え結果として 3 値をとる — 切り替え確定／取りやめで現状維持／`blog.json` の無いフォルダを退けて現状維持（退けたときだけ利用者に通知する）。確定したときはコンテンツルート記憶を書き換え、サーバーを停止して新しいプロジェクトで起動し直し、表示も入れ替える。以後の再起動でもそのプロジェクトが使われる。切り替えにアプリ外部の知識（永続化ストアの手動操作など）は要らない。

## 異常時の表示と診断ログ

正常なときにエラーに関する表示は一切現れない。サーバーライフサイクル連動はサーバープロセスの出力と予期しない終了を観測し、表示状態判定器はサーバーの生死と起動完了の観測から、失敗段階（起動失敗／起動後障害。境界は編集画面に到達したか）を含む表示状態を判定する。エラー表示は失敗段階・エラー内容・診断ログの場所から表示を組み立てる — 起動失敗なら「サーバーの起動に失敗しました」とエラーログと「ログを表示」（Finder で診断ログの場所を開く）、起動後障害なら「サーバーで問題が発生しました」。真っ白な画面だけが残る状態にはならない。

診断ログはサーバープロセスの出力の記録で、`~/Library/Logs/tenjuu99-blog/` に起動セッションごとのファイルとして書き出される（内容は `npm run server` 相当のログ）。診断ログ書き出しは起動のたびに新しいファイルに切り替え、直近 5 回分だけ残して古いものを消す。

コンテンツルートの解決に失敗したとき（選んだフォルダに `blog.json` が無い等）は、ダイアログでその旨を示してアプリを終了する。
