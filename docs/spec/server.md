# サーバー

HTTP リクエストをハンドラースクリプトに振り分ける拡張機構。`src/server/` にスクリプトを置くことで API エンドポイントを追加できる。ページの描画（SSGコア）、ファイル監視（開発サーバー）は扱わない。

## サーバーハンドラーの登録と振り分け

サーバーディレクトリは `.cache/server/` で、`src/server/` と有効なパッケージの `server/` の内容がキャッシュの仕組みで集約される（直下のファイルだけを読み、サブディレクトリは読まない）。サーバーハンドラーは、`path`（受け持つ URL パス）と HTTP メソッド名の小文字の関数（`get`・`post` 等）をエクスポートするスクリプト。ハンドラー登録は、拡張子を含まない URL への最初のリクエスト時に一度だけ全スクリプトを読み込み、`path` をキーに登録する（スクリプトを追加したらサーバーの再起動が要る）。

リクエストのパスが末尾 `/` でなく（末尾 `/` のパスは先に `index.html` が補われる）、かつ `.` を含まないとき、静的配信より先にハンドラーが試される。`path` が一致しメソッドの関数があればそれを実行し、戻り値が `true` なら応答済み、`{ status, contentType, body }` ならその内容で応答し、何も返さなければ静的配信（`.html` 付与）へ進む。ハンドラーが例外を投げた場合はログに出るだけで応答は返らず、静的配信へ進む（多くは 404 になる。500 にはならない）。
