## US-01: git の無い環境での同期操作

**ロール:** git をインストールしていない（または git を知らない）環境でアプリを使う執筆者
**目的:** 公開・更新・非公開・削除・取り込みの同期操作一式を、記事とその参照画像の両方について、手元の環境に git を用意せずに使いたい
**価値:** 配布されたアプリだけで執筆から公開までが完結する。将来、ローカルに git を持てない環境（iOS/iPadOS 等）への広がりの土台になる

### シナリオ 1: 記事を公開する

```
Given git がインストールされていない環境に、リモートと同期済みのコンテンツルートがある
And 新しい記事を書いて保存してある
When 公開の操作をする
Then 記事がリモートに反映され、公開済みになる
And 操作の過程で git の言葉（commit・push 等）が現れない
```

### シナリオ 2: 公開済みの記事を非公開にする

```
Given git がインストールされていない環境で、公開済みの記事がある
When 非公開の操作をする
Then 記事がリモートから取り除かれる
And 原稿は手元に残り、再公開できる
```

### シナリオ 3: 記事を削除する

```
Given git がインストールされていない環境で、公開済みの記事がある
When 削除の操作をする
Then 記事が手元からもリモートからも無くなり、残骸が残らない
```

### シナリオ 4: リモートの内容を取り込む

```
Given git がインストールされていない環境のコンテンツルートに対して、
      リモートには別のマシンで公開された新しい記事がある
When 取り込みの操作をする
Then 新しい記事が手元に現れ、続きを書ける
And 操作の過程で git の言葉（pull・merge 等）が現れない
```

### シナリオ 5: 画像を参照する記事を公開する

```
Given git がインストールされていない環境で、本文または frontmatter から画像を参照する記事を書いてある
When 公開の操作をする
Then 記事と参照画像の両方がリモートに反映され、記事も画像も公開済みになる
And 画像だけ届いていない・記事だけ届いている、という中途半端な状態にならない
```

### シナリオ 6: 画像の公開状態が git 手段と同じ意味で判定される

```
Given git がインストールされていない環境で、公開済みの記事が参照していた画像を、
      記事から参照しなくなった（またはリモートにだけ画像が残っている）
When 画像の一覧や記事の公開ステータスを見る
Then 画像の公開状態（公開済み・リモートに残存・未公開）が、git 運用のマシンで見たときと同じ読みで示される
And 残存している画像をリモートから取り除く操作ができる
```

### シナリオ 7: 別のマシンで公開された画像付き記事を取り込む

```
Given git がインストールされていない環境のコンテンツルートに対して、
      リモートには別のマシンで公開された画像付きの記事がある
When 取り込みの操作をする
Then 記事と参照画像の両方が手元に現れ、プレビューで画像が表示される
```

## US-02: git 運用のマシンとの混在

**ロール:** 複数のマシンを順に使い分ける執筆者（一方は git 運用、他方は git の無い環境）
**目的:** どのマシンで公開したかを気にせず、同じリモートを介して執筆を続けたい
**価値:** 既存の git 運用を壊さずに、git の無い環境を執筆環境の仲間に加えられる

### シナリオ 1: git 運用のマシンで公開した記事を、git の無い環境で取り込む

```
Given マシンA（git 運用）で記事を公開してある
When マシンB（git の無い環境）で取り込みの操作をする
Then マシンAで公開した記事がマシンBの手元に現れる
```

### シナリオ 2: git の無い環境で公開した記事を、git 運用のマシンで取り込む

```
Given マシンB（git の無い環境）で記事を公開してある
When マシンA（git 運用）で取り込みの操作をする
Then マシンBで公開した記事がマシンAの手元に現れる
And マシンAのその後の git 運用（公開・更新）が今まで通り機能する
```

### シナリオ 3: 既存の git 運用が退行しない

```
Given git 運用のマシンだけを使い続ける執筆者がいる
When 公開・非公開・削除・取り込みの操作をする
Then すべて従来どおりに機能する
```

## US-03: 執筆内容の保全

**ロール:** git の無い環境で執筆する執筆者
**目的:** 同期操作によって、書いたものを失いたくない
**価値:** 同期を恐れずに実行できる。「取り込んだら消えた」が起きない

### シナリオ 1: 両側で変わった記事は取り込みで上書きされない

```
Given git の無い環境で記事を編集してあり、
      同じ記事がリモートでも（別のマシンから）更新されている
When 取り込みの操作をする
Then 手元の編集内容は上書きされずに残る
And その記事の取り込みが見送られたことと理由が執筆者に伝わる
```

### シナリオ 2: 手元で編集しただけの記事が「見送り」になり続けない

```
Given git の無い環境で、同期済みの記事を手元で編集した
      （リモート側は変わっていない）
When 取り込みの操作をする
Then 手元の編集は「両側で変わった」と誤って扱われない
And その後の公開の操作で、編集内容をリモートに反映できる
```

### シナリオ 3: 手元で削除した記事が取り込みで戻ってこない

```
Given git の無い環境で記事を削除した（削除はまだリモートに伝播していない）
When 取り込みの操作をする
Then 削除した記事が手元に復活しない
```

## US-04: GitHub がホストするリモートとの互換

**ロール:** GitHub 上のリポジトリをリモートとし、そこから CI/CD でサイトを配信している執筆者
**目的:** git を使わない手段でも、今までと同じリモートに、今までと同じ形で届けたい
**価値:** リモートやデプロイの仕組みを変えずに、git の無い環境を加えられる。この一実装を通じて「第二の手段が公開の抽象に何を要求するか」が明らかになり、他手段への一般化の出発点になる

### シナリオ 1: 反映がリモートの形式を変えない

```
Given GitHub 上のリポジトリがリモートで、そこへの反映をきっかけにサイトが配信されている
When git の無い環境から記事を公開する
Then リモートは git 運用で公開したときと見分けのつかない形で更新される
And サイトの配信（デプロイ）が従来どおり起きる
```

### シナリオ 2: リモートが進んでいたら反映が拒まれる

```
Given git の無い環境で記事を編集している間に、別のマシンから同じリモートに公開があった
When git の無い環境から公開の操作をする
Then 別のマシンの公開を上書きせずに反映が拒まれ、先に取り込みが必要であることが執筆者に伝わる
```

### シナリオ 3: リモートへ届くための資格情報が手段の中で扱われる

```
Given git の無い環境で、リモートへ届くための資格情報が用意されている（獲得の手順は範囲外）
When 公開・取り込みの操作をする
Then 環境の git 設定に頼らず、その資格情報でリモートに届く
```
