## US-01: 公開手段を選べる

**ロール:** 作成者（配布を受けた、このリポジトリを知らない人。作者自身を含む）
**目的:** 設定ファイルの存在・形式を知らずに、アプリの中で公開手段を選び、選んだ手段に要るものを与えたい
**価値:** 「この手段なら git 無しで運用できる」ことが、選ぶ操作を通じて分かる。能力の存在を知るために spec や外部の助けを要しない

### シナリオ 1: 選択肢が見え、GitHub 手段を選べる

```
Given 手元に原稿フォルダがあり、エディタを開いている
  And 公開手段はまだ選んでいない（既定のまま）
When 公開手段を選ぶ画面を開く
Then git 手段と GitHub 手段が選択肢として見え、それぞれ何を前提にするか（git 手段は手元の git、GitHub 手段は認証情報）が読み取れる
  And GitHub 手段を選び、リモートの識別（所有者・リポジトリ・ブランチ）を与えると、選択が受け付けられる
```

### シナリオ 2: 選んだ手段が次に開いたときも保たれている

```
Given GitHub 手段を選び、リモートの識別を与えた
When エディタを閉じて開き直す
Then 選んだ手段とリモートの識別がそのまま残っている
```

### シナリオ 3: 選択肢の存在が能力の理解につながる

```
Given 手元に git が無いマシンで、GitHub 経由で運用できることを知らない
When 公開手段を選ぶ画面を開く
Then 「git 無しでも GitHub 経由で運用できる」ことが、選択肢とその説明から分かる
```

### シナリオ 4: 選択が別のマシンの運用を壊さない

```
Given 同じリモートを git 手段のマシンでも使っている
When 手元のマシンで GitHub 手段を選ぶ
Then git 手段のマシンの公開・取り込みは今までどおり動く
```

## US-02: 認証情報を用意できる

**ロール:** 作成者
**目的:** アプリの中で認証情報を登録・差し替えしたい。発行の仕方もアプリの中で知りたい
**価値:** 認証情報の置き場所や形式を知らなくても、手段がリモートへ届く状態を自分で作れる

### シナリオ 1: 発行の仕方が案内され、登録できる

```
Given GitHub 手段を選んでいるが、認証情報をまだ用意していない
When 認証情報を用意する画面を開く
Then GitHub でトークンをどこで・どんな権限で発行すればよいかの案内が読める
  And 発行したトークンを入力して登録すると、受け付けられたことが分かる
```

### シナリオ 2: 認証情報は手元だけに残る

```
Given 認証情報を登録した
When 記事を公開する
  And 共有設定・リモートの内容を確かめる
Then 認証情報は共有設定にもリモートにも含まれていない
  And 画面に平文の認証情報が残り続けていない
```

### シナリオ 3: 差し替えられる

```
Given 認証情報を登録済み
When 新しいトークンで登録し直す
Then 以降の公開・取り込みは新しい認証情報で行われる
```

### シナリオ 4: 認証情報が無いままの手段は、その理由が分かる

```
Given GitHub 手段を選んでいるが、認証情報を用意していない
When エディタで公開ステータスを見る、または公開しようとする
Then 認証情報が用意されていないために操作できないことが分かり、用意する画面へ辿れる
```

## US-03: 選んで用意すれば運用が始まる

**ロール:** 作成者
**目的:** 手元に原稿フォルダがあり、リモートに資材一式がある状態から、選択と用意だけで既存の同期操作を使い始めたい
**価値:** 設定ファイルを一切手で触らずに、GitHub 経由の運用が始まる

### シナリオ 1: 設定ファイルに触れずに公開できる

```
Given 手元に原稿フォルダがあり、リモートに資材一式（ビルド・デプロイに要るもの）が既にある
  And 手元に git は無い
When アプリの中で GitHub 手段を選び、リモートの識別を与え、認証情報を登録する
  And 記事を編集して「公開する」を実行する
Then 記事がリモートに届き、配信が今までどおり起きる
  And この間に blog.json や認証情報のファイルを手で編集していない
```

### シナリオ 2: 既存の同期操作が git 手段のときと同じ意味で動く

```
Given シナリオ 1 の状態
When 記事の更新・非公開・削除・リモートからの取り込みを実行する
Then それぞれが git 手段のときと同じ意味で反映され、公開ステータスの読みも同じである
```

## US-04: web エディタに作られ、native app にも載る

**ロール:** 作成者（native app の利用者）
**目的:** native app からも、同じ選択・用意ができるようにしたい
**価値:** 本来の用途である native app で、追加の仕組みなしに手段の選択と認証情報の用意ができる

### シナリオ 1: native app で同じ画面に辿れる

```
Given native app でコンテンツルートを開いている
When 公開手段を選ぶ画面・認証情報を用意する画面を開く
Then web のエディタと同じ操作で選択・登録ができ、その結果が同じように保たれる
```
